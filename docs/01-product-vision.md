# 01 · Product vision

## One sentence

**MediFlow is a cloud ERP for Indian pharmacy chains whose billing counter keeps working offline, built to replace Marg-style desktop software.**

## Who it is for (in priority order)

1. **Multi-store pharmacy chains (primary).** 3–50 branches, often with a central warehouse or "head office" store. Their pain is visibility and control across branches. They need to know what stock sits where, which branch is about to lose stock to expiry, and which branch has a cashier giving unauthorised discounts. They also need to move stock between branches, buy centrally, and file GST for every GSTIN they hold.
2. **Single chemist shops.** Same product with one store. They get it "for free" once the chain features work, because a chain of one is a single shop.
3. **Clinic / hospital dispensaries (later).** They need patient-centric flows (OPD visit → prescription → dispensing). The schema already has `prescriptions` and `doctors`, so this is an extension, not a rewrite.

## What "complete ERP" means for us

An ERP connects every department's records so that one action updates everything it affects. For a chain, the full loop is:

```
 Supplier ──PO──► Purchase / GRN ──► Stock (batches) ──► Sale (POS) ──► Customer
    ▲                 │                  │    ▲  │            │
    │                 ▼                  ▼    │  ▼            ▼
 Payments ◄── Accounts payable     Transfers between stores   Accounts receivable, loyalty
    │                                                         │
    └──────────────► Double-entry ledger ◄────────────────────┘
                          │
                  GST returns (GSTR-1, 3B), e-invoice, statutory registers, reports
```

Every arrow in that diagram must be automatic. If a pharmacist has to type the same information twice, we have a gap.

## How we win

| Competitor | Their strength | Their weakness | Our answer |
|---|---|---|---|
| **Marg ERP** | Market leader. Deep accounting, works offline, every CA knows it. | Desktop-first, dated DOS-style UI, multi-store sync is painful, licence-priced (~₹10k+/yr per install). | Same keyboard speed in a modern UI, real-time multi-store cloud, and offline billing that syncs. A **one-click Marg import** so switching costs nothing. |

Treat them as indicative ([techimply](https://www.techimply.com/blog/pharmacy-management-system), [accountune](https://accountune.com/best-billing-software-medical-store-india), [codingclave](https://codingclave.com/blog/best-pharmacy-software-india-2026)).

### Differentiators to protect

1. **Speed at the counter.** Bill a 5-item prescription in under 30 seconds, keyboard only. This is the #1 reason pharmacists refuse to switch.
2. **Offline billing.** Indian shops lose internet regularly. A cloud POS that stops billing loses the customer on day one.
3. **Correct by construction.** Integer paise, an immutable stock ledger, and double-entry journals generated from every transaction. Pharmacists trust software that never "loses" a strip.
4. **Compliance without effort.** Schedule H/H1/X registers fill themselves from POS sales, and GSTR-1 is generated, not typed.
5. **Chain control.** Owner-level dashboards across branches, plus role-based permissions so cashiers can't see margins or give unapproved discounts.
6. **AI that does chores.** "Which items will expire at Branch 3 next month and which branch can sell them?" Or "Draft this week's purchase order." Reorder suggestions, substitute suggestions and expiry redistribution.

## Non-goals (for the first 6 months)

- Wholesale/distributor billing (C&F, stockist credit schemes). The schema doesn't stop it later.
- HR and payroll.
- Customer-facing mobile app or storefront. Online orders arrive via WhatsApp and the `/api/v1/orders` API instead.
- Native mobile apps. The web app is responsive and installable as a PWA.

## Success criteria for "v1 sellable" (end of roadmap)

- A 3-branch chain can run **all** daily operations for a month without falling back to Marg or paper.
- The POS survives a 2-hour internet outage with zero lost bills.
- GSTR-1 JSON generated by MediFlow is accepted by the GST portal's offline tool without manual edits.
- A shop's Marg data (items, batches, customers, suppliers, opening balances) imports in under an hour.
- Every money and stock path has automated tests. CI must pass before every merge.
