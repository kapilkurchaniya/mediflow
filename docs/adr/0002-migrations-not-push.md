# ADR 0002 · Committed SQL migrations, not `drizzle-kit push`

- **Status:** accepted · 2026-10-20

## Context
The local databases were built with `drizzle-kit push`. `drizzle/0000_init.sql` covers 37 tables while the schema defines ~58. A fresh environment (CI, a new developer, production) can't be built reliably, and two developers pushing different schemas silently diverge.

## Decision
- All schema changes ship as SQL files generated by `drizzle-kit generate` and committed in `drizzle/`.
- Databases are only changed by `npm run db:migrate` (`src/server/db/migrate.ts`).
- `push` is allowed only against a throwaway local DB.
- One migration per PR, regenerated after merging `main` (procedure in `docs/04-database.md`).
- Merged migrations are immutable; fix forward.

## Consequences
- Lane A creates a one-time catch-up migration (`0001_catch_up`) in Phase 0. Developers recreate their local DBs.
- Slight friction when both lanes change the schema in the same week. The merge-then-regenerate rule handles it.
- Production deploys run `db:migrate` before starting the new app version.
